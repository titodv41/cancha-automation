# Photo editorial workflow

Use when the owner asks for posts about identifiable clubs, people, events or news. Read `config/growth-content-policy.json`: directory profiles are not members or partners; urgency must come from genuine dates, availability or an early-building invitation. Follow the current owner's scope and publishing instructions. The Cancha owner confirms handling permissions for this project’s subject media (recorded October 22, 2026); the recorded reference is `owner-cleared-2026-10-22`. This is not a license claim or a grant for a different project.

1. Read `docs/photo-editorial-workflow.md`, the current editorial policy and account identity. Inspect the real queue before changing scheduled work. Preserve published and uncertain publication receipts.
2. Read the official story, check current facts and dates, and register exact source documents/facts/expiry in `config/local-editorial-sources.json`. Prefer original club reporting. Do not invent quotes, availability, supporters, affiliations, ticket offers or interviews. An old proposal is not a new opening.
3. Find actual photos of that subject on the recorded source pages. View every photograph. A generic ball, unrelated player, sponsor logo or generated portrait cannot stand in for the subject. Record publisher, subject, URL and SHA-256. Use the owner's media assurance already recorded in this session; don't repeatedly request it.
4. Edit `content/instagram/photo-editorial.json`. Keep 3–5 slides and one idea per slide: hook, useful context, question/action. Use concise language, Cancha display titles, readable Barlow body type and genuine photography. Keep provenance and technical notes out of artwork. Never remove a necessary event date or closed-registration status just to simplify the design.
5. Run `npm run content:photos`, inspect every slide and a phone-sized overview, fix crops/overflow, then run `npm run content:photos -- --upload`. Public URLs and hosted-byte checksums go into `photo-editorial-ready.json`.
6. Render the configured video with `npm run content:video`. Inspect three key frames and the actual MP4. It is a photo-led recap, not real match footage. For motion stories, use the exact official club clip or owner-supplied file, animate the topic, and use original/cleared audio. `content:voice-setup` installs the free local narrator; `content:motion` builds the 22-second template. No cloned player/coach voice or invented quotation. Reels now have a separate verified media-container path; they count within the two daily feed posts and wait for a same-day carousel publication.
7. After inspecting a motion render, run `node scripts/prepare-motion-queue.mjs` and use the `refresh-motion-stories` action. A change to the story, brand, narration or renderer requires a new render. Run relevant tests, push the reviewed change, then dispatch `refresh-photo-stories`. Read its successful result and queue artifact. It can replace only a future, untouched standing-plan approval; it keeps that exact slot. It never overwrites Preparing/Publishing/Published/uncertain work or a separate manual approval.
8. Share working public HTTPS previews. Explain what is a Draft, Approved, Published or video preview. Never imply that source selection, new creative production or performance learning runs continuously unless an actual job does it.

For another brand, replace the manifest's logo/fonts/colors/handle, reviewed source registry, authorization reference in `approvedSubjectPhoto`, expected account config and secure credential bindings. Start with render-only and a separate queue; do not reuse Cancha's connected account, approval history or secrets.
