# Soccer motion

Use for Cancha's club clips, match moments and soccer news explainers. Preserve the approved photo-carousel style; do not rebuild the brand or expand the daily publishing cap. Read `docs/motion-and-honest-growth.md`, `config/growth-content-policy.json` and the current editorial policy first.

1. Inspect the actual connected queue and preserve its published/uncertain receipts and imminent approvals. Use the owner's standing publishing instructions. Never pretend the workspace is an always-running researcher.
2. Read an accessible official source. Establish what happened, when, where and why a local player or fan would care. A plan, vote or proposed stadium is not a completed launch. If a league site is blocked, document it and use a different verifiable story rather than inventing an update.
3. Pick a visual structure: actual club action for a match moment; original diagrams, maps, arrows and a relevant official photo for an explainer. No unrelated highlights, generated footage presented as a real match, fabricated speakers or implied interviews. Record exact source identity and checksums.
4. Write one spoken idea per sentence, in normal soccer language. Prefer “Weston FC. MLS NEXT. A two–nil win.” over “the club reports…” when the fact is supported. Keep the source record in evidence/caption links. Preserve material words such as planned, closed or registration date in the visible story.
5. Keep the real action visible in the first second. Use short title beats, generous safe areas and legible supporting type. Animate a useful process, result, location or comparison; avoid decorative movement that competes with the topic. Use frame-driven easing and brief overlapping transitions, never CSS animation or random timing.
6. Run `npm run content:voice-setup`. The pinned full-precision Kokoro model and generic 80/20 Heart/Bella blend run locally without API fees. Use complete conversational phrases, measured timings and modest per-phrase rate changes. Do not clone a player/coach or write a fake quotation. Never claim the synthetic voice is a real person.
7. Use an original/cleared upbeat track, restrained transition sounds, gradual music ducking and consistent loudness. Keep source clip audio separate unless it is deliberately selected and usable. Measure voice overlap, clipping, audio channels and output duration.
8. Render the full audiovisual output, inspect key/transition frames and phone playback, check every factual caption and read the source again. A changed script, brand, model lock or renderer requires a new render. See `video/render-contract.mjs`.
9. Upload only reviewed immutable public media; private downloads, weights and intermediates stay ignored. Import through the supported GitHub workflow. Reels share the two-post daily cap and wait for an actual same-day carousel publication. Retain Meta's appropriate synthetic-media disclosure, without printing production notes on the design.
10. Share a working HTTPS preview and accurate queue status. Distinguish source-checked drafts, scheduled approvals and actual Instagram publications. Record the evidence and blockers in the workflow documentation.

Reference guidance: [official Remotion skills](https://github.com/remotion-dev/skills/tree/main/skills/remotion-best-practices), especially creation, markup, transitions, audio and measured voiceover timing. Keep versions pinned to this project. The owner has authorized rendered previews and a free local voice; generic provider recommendations do not require purchasing ElevenLabs or asking for a key.

OpenMontage was evaluated as an optional larger orchestrator. This workflow already has Remotion, FFmpeg, source validation, voice, music and a durable publisher; do not add another service merely to improve a transition. The Chatterbox Nano trial is documented in the motion guide; other voice models remain optional comparisons and must pass the same delivery and readback checks.
